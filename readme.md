# vit_optica

Vision Transformer с **оптическим матричным умножением** (численная модель 4f-системы)
и серия экспериментов: точность классификации при подстановке оптики в разные части
модели, при разной апертуре, и тесты утечки. Устроен так же, как `optic_train`:
один скрипт `main.py` с аргументами, `run.sh` с полным планом, JSON с результатами.

Сравниваются способы умножения при прочих равных:

- `digital` — `torch.matmul` (эталон);
- `shift` — сдвиг в положительную область (1 вызов sim на умножение);
- `split` — разложение на положительные и отрицательные части (до 4 вызовов).

## Датасет

Для сравнения **обучения с нуля на оптике и в цифре** по умолчанию используется
**Imagenette** (10 классов ImageNet, ~9,5 тыс. обучающих и ~3,9 тыс. проверочных
фотографий), для более трудной задачи с той же стоимостью — **Imagewoof** (10 пород
собак, тонкая классификация). Изображения 160×160 — реальное разрешение фотографий
версии 160px, патч 20×20, то есть 64 патча + CLS = 65 токенов, как на CIFAR-10.

Число токенов, а не пикселей, определяет стоимость оптики: патч-эмбеддинг цифровой.
Поэтому разрешение можно поднять до 224 (`--img_size 224 --patch 28`, берётся версия
320px) без роста стоимости вызовов sim. Обучающих изображений в ~5 раз меньше, чем в
CIFAR-10, поэтому эпоха с оптикой примерно в 5 раз дешевле, и полное обучение с оптикой
с нуля становится посильным.

Также поддерживаются `tinyimagenet` (200 классов, 64×64, патч 8; в 2 раза дороже
CIFAR-10 по числу изображений), `cifar10`, `cifar100` и `fake` (проверка кода).

```bash
python -m vit_optica.main --dataset imagenette --download 1 ...
```

Из обучающей части выделяется фиксированная валидационная выборка (`--val_fraction`,
по умолчанию 5 %). По ней выбирается лучшая эпоха; тест используется только для итога.
В JSON пишутся точность на тесте на последней эпохе и на эпохе с лучшей валидацией.

## Модель

ViT шириной 192, 12 блоков, 6 голов по 32, MLP 192 → 384 → 192 (`--mlp_ratio 2`),
LayerScale, stochastic depth, финальный LayerNorm. MLP×2 выбран, чтобы все матрицы
(максимум 384) помещались в поле 512 той же 4f-системы, что в `optic_train`; при
MLP×4 нужно `--aperture 768` или больше (скрипт проверяет это при старте).

Вход: `--stem patch` — обычная нарезка на патчи; `--stem conv` — свёрточный стебель
(несколько свёрток 3×3 с шагом 2 + BN + ReLU, затем свёртка до той же сетки токенов).
Стебель цифровой, как и патч-эмбеддинг: число токенов и стоимость оптики не меняются,
а ViT на малых данных получает недостающую локальность. При загрузке чекпоинта
`--stem` и порядок токенов берутся из него. Регуляризация: CutMix (`--cutmix_prob`) и
MixUp (`--mixup_alpha`, применяется на батчах без CutMix).

Места оптики: `--optic_where` из `ff`, `proj` (q, k, v, o), `qk`, `av` через `+`, либо
`all` / `attn`; `--optic_layers N` — оптика только в N блоках, равномерно по глубине.

## Запуск одного эксперимента

```bash
cd /wd
# цифровое обучение
python -m vit_optica.main --dataset tinyimagenet --mode digital --epochs 200 --comment digi_raster
# инференс с оптикой на цифровых весах
python -m vit_optica.main --dataset tinyimagenet --mode split --optic_where all \
    --lens_size 16384 --eval_only 1 --load_ckpt runs_vit/ckpt_digital_digi_raster.pt --comment inf
# дообучение с оптикой
python -m vit_optica.main --dataset tinyimagenet --mode shift --optic_where ff+proj \
    --load_ckpt runs_vit/ckpt_digital_digi_raster.pt --epochs 10 --lr 1e-4 --comment ft
```

Проверка кода без GPU и данных:

```bash
python -m vit_optica.main --dataset fake --mode split --optic_where all --stub_sim \
    --stub_blur 0.02 --epochs 1 --h_dim 64 --depth 2 --heads 4 --workers 0 --comment smoke
```

## Полный план (`run.sh`)

Сначала замер скорости: `bash vit_optica/run.sh probe` прогоняет по 20 итераций каждой
конфигурации фазы `scratch` и печатает прогноз времени на весь бюджет эпох
(`python -m vit_optica.collect_results` выводит сводку замеров). По нему решается,
какие конфигурации запускать (`FORMULAS`, `SCRATCH_WHERE`, `SCRATCH_LENSES`, `EPOCHS`).

| Фаза | Что делает | Запусков |
|---|---|---|
| `probe` | замер с/итерацию и прогноз времени для `scratch` | 7 |
| `scratch` | обучение с нуля одним рецептом: цифра (3 сида) и shift/split × {qk+av, ff+proj, all} | 9 |
| `cross` | веса с оптики: в цифре и при другой апертуре; цифровые веса — с той же оптикой | 18 |
| `digital` | цифровое обучение со случайным порядком патчей | 1 |
| `infer` | цифровые веса + оптика: shift/split × 7 мест × 2 апертуры, плюс split с глобальной нормировкой | 29 |
| `order` | веса со случайным порядком патчей: важна ли структура смешивания | 4 |
| `layers` | 1/3/6/12 блоков с оптикой во внимании (аналог таблицы CIFAR-10) | 4 |
| `noise` | точное умножение с шумом σ в ff+proj: ошибка/σ даёт коэффициент усиления κ | 6 |
| `finetune` | дообучение с оптикой, shift/split × {ff+proj, all} × апертура | 8 |

```bash
DATASET=imagenette bash vit_optica/run.sh probe
DATASET=imagenette bash vit_optica/run.sh scratch
DATASET=imagewoof  SCRATCH_WHERE="all" bash vit_optica/run.sh scratch
DRY=1 bash vit_optica/run.sh     # только команды
python -m vit_optica.collect_results ./runs_vit ./runs_vit/summary.csv
```

Что даёт сравнение: разница «цифра − оптика» при одинаковом рецепте, сравнённая с
разбросом цифры по сидам; перекрёстная оценка показывает, адаптировались ли веса к
конкретной ошибке оптики (точность тех же весов в цифре и при другой апертуре).

## Где результаты

Всё пишется в `--out_dir` (по умолчанию `./runs_vit`, в `run.sh` — переменная `OUT`);
имя запуска — `<режим>_<comment>`:

- `<имя>.json` — итог: аргументы, точность на валидации и тесте (последняя эпоха и
  эпоха с лучшей валидацией), top-5, ошибки по семействам умножений, тесты утечки,
  журнал по эпохам, время;
- `ckpt_<имя>.pt` — веса последней эпохи и лучшей по валидации (только если было обучение);
- `log_<comment>.txt` — полный вывод консоли (пишет `run.sh`);
- `probe_<имя>.json` — замеры скорости;
- `tb/<имя>/` — кривые TensorBoard: `Loss/train`, `Loss/val`, `Accuracy/val`, `LR`,
  `Time/epoch_sec`, итоговые `Final/*` и `LayerError/*`.

```bash
tensorboard --logdir ./runs_vit/tb --port 6006
python -m vit_optica.collect_results ./runs_vit ./runs_vit/summary.csv
```

## Что значит «утечка» для ViT

В языковой модели утечка — это информация о **последующих** токенах, запрещённая
постановкой задачи. В ViT внимание двунаправленное, каждый патч законно видит все
остальные, а метка во вход не попадает, поэтому такой утечки нет, и точность
классификации остаётся корректной мерой качества. Проверяются эффекты, которые остаются:

1. **Перекрёстное влияние соседних позиций** (`leak.operator`): изменение токена j
   меняет результат там, где при точном умножении не должно. `linear_rows` — строки
   левого операнда (должно быть ~0: строки распространяются независимо); `qk_cols` и
   `qk_profile` — столбцы k^T, в том числе по расстоянию |l − j|; `av_zero_weight` —
   влияние v_j при нулевом весе внимания на токен j. Рядом — цифровой контроль.
2. **Утечка между примерами батча** (`*_batch`, `leak.model_batch`): меняются только
   остальные примеры батча. Численная модель однородна первой степени по каждому
   операнду (sim(cX, Y) = c·sim(X, Y)), поэтому нормировка на максимум сокращается и
   примеры не связывает даже при `--split_norm global`; тест это подтверждает.
   Связь появилась бы при шуме или квантовании, зависящих от полной шкалы.
3. **Влияние на точность**: сравнение ff/proj против qk/av, апертуры 16384 против
   32768, порядка токенов raster против random.

## Что исправлено по сравнению с прежней версией

- CutMix: модель прогонялась дважды на батч (удвоение времени и разные подсети при
  dropout) — теперь один прямой проход.
- Лучший чекпоинт выбирался по тесту — теперь по отдельной валидационной выборке.
- `noise_std` читался, но не применялся — шум реализован в заглушке sim (`--noise_sigma`).
- `source.OpticalDataParallel` нет в публичном симуляторе — используется `ParallelSim`.
- Симулятор регистрировался в каждой голове внимания (буферы дублировались в
  state_dict) — теперь хранится один раз в `OpticContext`.
- Жёсткие пути `/wd/...`, нет сида, случайный порядок оценки — исправлено; оценка
  идёт с фиксированным порядком и одинаковым размером батча во всех запусках.
- Нормировка split по всему батчу — добавлена нормировка по каждой матрице (по умолчанию).
- Калибровка по одной форме 512×512 — по умолчанию `g` калибруется отдельно для
  каждой формы умножения (`--calibrate 2`), значения пишутся в JSON.
- Оптика только во внимании — теперь можно в любых подмодулях, как в `optic_train`.
- Добавлен финальный LayerNorm; `optic_layers` распределяет блоки равномерно по глубине.

Файлы прежней версии `config.py`, `trainer.py`, `analisys.py`, `profiler.py`,
`OPTICAL_LAYERS_README.md` больше не используются.
